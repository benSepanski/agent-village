# agent-village 1.0 — local-dogfood verdict (M6)

Author: Opus verdict pass, M6. Binding ACs: [`1.0-definition.md`](1.0-definition.md).
Evidence: five persona logs under the M6 scratchpad `m6-evidence/`
(`platform-operator.md`, `operator.md`, `app-builder.md`,
`spend-limit-victim.md`, `auditor.md`) plus milestone status docs
`status-m1.md`…`status-m5.md`. This is the written local-dogfood verdict
required by **AC-7.4**, recorded before any AWS deploy is attempted.

The single fact that shapes this whole verdict: **the local stack has no API
server, no runner, and no local Cognito.** `pnpm local:up` + `pnpm dev` stand up
LocalStack (Secrets Manager), DynamoDB Local, and the Vite SPA — nothing else.
No `local.ts` infra config, no `dev` script for `api`/`services`/`runner`, no
`createServer`/`listen` in the API layer (platform-operator #9–#11, #57;
independently reconfirmed by every other persona). Consequently **no run, agent,
user, or spend record was ever created locally** (auditor #2: full DynamoDB scan
returns `Count: 0`), and **no human/agent can get past the sign-in screen**
(operator [5]–[9]; the mock-auth seam is Playwright-`addInitScript`-only and does
not help a live browser). This does not indicate broken mechanisms — it means
every AC whose verification is "manual-dogfood" against live behavior is
**structurally unexercisable locally** and legitimately moves to M7. The unit and
integration layers, by contrast, are green and were re-run this milestone.

## Headline verdict: **ready-for-dev-deploy**

Choosing honestly among the four options: not **needs-security-work** (no auth
bypass, injection, or credential-exposure defect was found; the Infinity-budget
issue is a validation-robustness gap, not a vulnerability); not
**feature-complete-needs-live-verification** (that overstates — Finding E is a
genuine gap in a _binding_ bar item, "spend walls must be transparent," and the
missing email/password affordance in the rendered SPA is an open feature
question, so the product is not feature-complete); and not **needs-testing** as
the primary story (enforcement, extensibility, and connectivity carry real,
green, re-run unit/integration coverage — the testing gap is narrow and named).

**ready-for-dev-deploy** is the accurate call, in the precise sense the M6→M7
gate asks for: _nothing found in the local dogfood blocks standing up the M7 dev
environment, and a dev deploy is the only surface on which the eight NEEDS-LIVE
criteria (AC-1.2, 1.4, 2.7, 3.2, 3.3, 3.4, 5.5-deploy, 7.5) and the live halves
of the PARTIALs can actually be verified._ The two FAILs (AC-7.1, AC-7.3) are
both root-caused to the same local-stack limitation (no local API/Cognito), which
is out of scope to fix (building a Lambda/Cognito emulation layer is not a
"trivial unblocking fix") — they are not deploy blockers, they are the reason the
real dogfood must happen at M7. The backend spend-enforcement core, which is the
riskiest and most owner-critical subsystem, is the _strongest_ part of the
evidence: atomic dual-cap transaction, deterministic tie-break, rollover
handling, and drift reconciliation are all tested and green.

The one caveat that keeps this from being an unqualified "go": **Finding E must
be fixed before 1.0 signoff, and ideally before M7.** It is a frontend-only
change, it is cheap, and if left in place the M7 live dogfood will simply re-flag
it — a user who hits a real budget wall will see the "Run now" button settle with
zero on-screen explanation, which fails the transparency bar the owner set. Fix
it pre-M7 so the live dogfood validates the transparent-rejection path instead of
re-discovering its absence.
