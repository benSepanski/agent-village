# agent-village 1.0 — local-dogfood verdict (M6)

Author: Opus verdict pass, M6. Binding ACs: [`1.0-definition.md`](1.0-definition.md).
Evidence: five persona logs under the M6 scratchpad `m6-evidence/`
(`platform-operator.md`, `operator.md`, `app-builder.md`,
`spend-limit-victim.md`, `auditor.md`) plus milestone status docs
`status-m1.md`…`status-m5.md`. This is the written local-dogfood verdict
required by **AC-7.4**, recorded before any AWS deploy is attempted.

The single fact that shapes this whole verdict: **the local stack has no API
server, no runner, and no local Cognito.** `pnpm local:up` + `pnpm dev` stand up
LocalStack (Secrets Manager), DynamoDB Local, and the Vite SPA — nothing else.
No `local.ts` infra config, no `dev` script for `api`/`services`/`runner`, no
`createServer`/`listen` in the API layer (platform-operator #9–#11, #57;
independently reconfirmed by every other persona). Consequently **no run, agent,
user, or spend record was ever created locally** (auditor #2: full DynamoDB scan
returns `Count: 0`), and **no human/agent can get past the sign-in screen**
(operator [5]–[9]; the mock-auth seam is Playwright-`addInitScript`-only and does
not help a live browser). This does not indicate broken mechanisms — it means
every AC whose verification is "manual-dogfood" against live behavior is
**structurally unexercisable locally** and legitimately moves to M7. The unit and
integration layers, by contrast, are green and were re-run this milestone.

## Evidence-skeptic pass

This verdict and `status-m6.md` were first committed **without** the
evidence-skeptic pass — that pass died on a session limit and was completed
afterward; both docs were then revised in place to reflect it (see the note in
`status-m6.md`). What the skeptic did and found:

**Method.** Re-traced every PASS/PARTIAL to primary evidence; re-executed 18
claims directly against the repo (HEAD `1d6e124`, branch `claude/m6-dogfood`);
audited the auditor persona against the committed `audit-a-run.md`. The stack had
already been torn down (no containers, no listening ports) and was **not**
restarted — all checks are repo-level, so none of the NEEDS-LIVE holes were
closed by this pass (nor could they be).

**Direction survives.** The headline **`ready-for-dev-deploy`** stands. Every
re-executed check matched the verdict: data spend/budget suites (47 pass),
services suites (49), shared schema suites (37), `sandbox-egress` (11),
`proxy-allowlist` (27), `config`, `apply-bot-fixture` (6), `synth-snapshot`
(2), `web-stack` throw-on-missing-dist, `mvp.spec` un-`fixme`'d with the
`replayOfRunId` assertion, the S3 `versioned: true` + `noncurrentVersionExpiration`
sandbox config, and the "only `web` has a `dev` script / no `local.ts` / no
`createServer` in api/services/runner" root cause of the two FAILs. Finding C
(`Infinity`→`true`, `NaN`→`false`, `JSON.stringify(Infinity)`→`null`) reproduced
exactly.

**Rejected / corrected evidence (drove this revision):**

- **Tally arithmetic (skeptic #1, mechanical).** The summary line said "14 PASS ·

## Headline verdict: **ready-for-dev-deploy**

Choosing honestly among the four options: not **needs-security-work** (no auth
bypass, injection, or credential-exposure defect was found; the Infinity-budget
issue is a validation-robustness gap, not a vulnerability); not
**feature-complete-needs-live-verification** (the two FAILs — AC-7.1/7.3, both
the local no-API/no-Cognito block — already mean the product is not
feature-complete, and Finding E, even at its corrected narrower MED scope, still
leaves the two spend-facing mutations swallowing rejections, while the missing
email/password affordance in the rendered SPA is an open feature question); and
not **needs-testing** as the primary story (enforcement, extensibility, and
connectivity carry real, green, re-run unit/integration coverage — the testing
gaps are narrow and named: AC-2.6/Finding F's absent budget-UI E2E, and AC-1.1's
unbacked traceId-propagation integration assertion).

**ready-for-dev-deploy** is the accurate call, in the precise sense the M6→M7
gate asks for: _nothing found in the local dogfood blocks standing up the M7 dev
environment, and a dev deploy is the only surface on which the seven NEEDS-LIVE
criteria (AC-1.2, 1.4, 2.7, 3.2, 3.3, 3.4, 7.5) and the live halves of the
PARTIALs can actually be verified._ (The original commit wrote "eight … 5.5-deploy"
here — that double-counted AC-5.5, which the scorecard scores PARTIAL; the
skeptic corrected it.) The two FAILs (AC-7.1, AC-7.3) are
both root-caused to the same local-stack limitation (no local API/Cognito), which
is out of scope to fix (building a Lambda/Cognito emulation layer is not a
"trivial unblocking fix") — they are not deploy blockers, they are the reason the
real dogfood must happen at M7. The backend spend-enforcement core, which is the
riskiest and most owner-critical subsystem, is the _strongest_ part of the
evidence: atomic dual-cap transaction, deterministic tie-break, rollover
handling, and drift reconciliation are all tested and green.

The one caveat that keeps this from being an unqualified "go": **Finding E should
be fixed before M7** (severity corrected to MED by the skeptic, down from HIGH —
it is a two-flow omission, not the architecture-wide gap the first draft
described). It is a cheap frontend change: `RunNowSection` and the budget-edit
mutation need to adopt the inline `mutation.error` idiom the create-agent route
(`agents.new.tsx:26`) already uses. If left in place the M7 live dogfood will
simply re-flag it — a user who hits a real budget wall on run-now will see the
button settle with zero on-screen explanation. Fix it pre-M7 so the live dogfood
validates the transparent-rejection path on the spend flows instead of
re-discovering its absence.
